# ローカルの複数模擬ユーザーで対戦・観戦を試す

## 起動

Windows / PowerShell 7 / Python 3.9以降 / ソースを実行できるLÔVEエンジンと、変換済みの `assets/` が必要。

リポジトリのルートで実行する。

```powershell
# 3人：ホストが観戦、残り2人が対戦する構成など
pwsh -NoProfile -File tools/start-mock-online.ps1

# 4人：対戦に参加しないホストと、別の観戦者も用意する構成など
pwsh -NoProfile -File tools/start-mock-online.ps1 -Players 4
```

既定のエンジンは `C:/Users/Owner/source/repos/lhat-love/build/love/Release/love.exe`。
別の環境では `-Engine "エンジンの絶対パス"`、Pythonの実行コマンドが異なる場合は `-Python py` などで指定する。
配布用のVM専用エンジンではなく、L^ソースを実行できる開発用エンジンを使う。

この作業環境の `.vscode/tasks.json` にも **Run local mock online (3 players)** / **(4 players)** を登録した。
`.vscode/` は従来どおりGit管理対象外。

## 操作

各ウィンドウは640×480で起動し、`LOCAL 1`〜の番号と実行ごとの識別子をタイトルに表示する。
最初の4ウィンドウは2列に配置する。開始演出をスキップし、模擬ユーザーでログインしたOnline VSのメニューを自動で開く。

1. `LOCAL 1` で「ルームを作成」を選び、Enterで作成する。
2. `LOCAL 2` と `LOCAL 3` は「ルームを探す」で同じルームに参加する。暗証番号なしなら、そのままEnterで入れる。
3. `LOCAL 2` と `LOCAL 3` を同じ対戦台の1Pと2Pにそれぞれ着席させ、もう一度決定して双方をREADYにする。
4. `LOCAL 1` で対戦中の台を選び、決定するとホスト自身の観戦になる。
5. `LOCAL 4` も入室させれば、第三者への中継も試せる。途中ラウンドで観戦を始めると、そのラウンドの先頭から自動早送りする。

各ウィンドウをクリックしてから通常のキー操作を行う。既定の決定はZ、戻るはX / A、ルーム退出・観戦終了はEsc。
キャラクター選択も通常どおり行い、試合に入ってから両方の対戦ウィンドウでF3を押せば、それぞれのローカル側をCPUに任せられる。
ホストが対戦に参加する構成を試す場合は、`LOCAL 1` と `LOCAL 2` で対戦し、`LOCAL 3` から観戦する。

ゲームのウィンドウをすべて閉じるとランチャーと中継サーバーも終了する。タスクの停止・Ctrl+Cでも、ランチャー自身が起動したプロセスだけを終了する。

## 設定とログ

作業用ファイルは `build/mock-online/<実行ID>/playerN/` に生成する。
元の `src/online.lh` をコピーし、ネイティブ `eos` のimportだけを開発用の `mock-eos.lh` に差し替える。
ロビーの入室判定・PIN・席・READY、対戦同期と巻き戻し、観戦の配信・再生は通常のゲームコードを使う。
素材の `assets/` と `data/` はjunctionで共有し、画像・音声を人数分コピーしない。

設定・リプレイの保存先は各ウィンドウに固有の `vanguard-mock-<実行ID>-<番号>` identityを使う。普段のゲーム設定や実EOSのキャッシュ・認証情報は使わない。
Epicアカウント、実EOSの設定、模擬EOSのネイティブDLLはいずれも不要。このランチャーの部屋は同じ実行で起動したウィンドウ間だけで見え、実際のEOS上の部屋とは接続しない。

ログは各 `playerN/output.log` / `error.log` と、実行フォルダ直下の `broker.log` / `broker-error.log`。
起動した実行フォルダはターミナルにも表示する。

## 開発用通信

従来の `eos_lhat_mock.dll` はプロセス内のメモリで状態を共有するため、複数プロセスの手動操作には使えなかった。
このランチャーではPythonのローカル中継サーバーと、L^で書いたEOS API代替を使う。

サーバーは `127.0.0.1` の自動割当UDPポートだけで待ち受ける。実行ごとにランダムなトークンを生成し、別のランチャー実行との混線を防ぐ。
要求と通知には連番・ACK・再送・重複排除・順序復元を付ける。ゲームのバイナリパケットはバイト値の配列に変換して、JSONのUTF-8処理で壊れないようにする。
アカウントはウィンドウごとの `local-player-N`。ルーム作成・検索・入室・メンバー通知・P2P中継・退出をサーバーが模擬する。

これはゲーム処理と複数ウィンドウの動作確認用。実EOSの認証、NAT越え、サービスの遅延や損失特性を検証するものではない。

## 検証

```powershell
# 4つの独立プロセスで自動確認し、完了後はすべて終了する
pwsh -NoProfile -File tools/start-mock-online.ps1 -Check

# 中継サーバーの再送、順序、重複、退出、実行トークンの確認
python tools/mock-online/test_broker.py
```

`-Check` は別プロセスのルーム作成・PIN付き入室・席とREADY・両者のバイナリ入力・ホストの観戦受信・第三者の最新ラウンドからの観戦受信・分割されたUTF-8開始データ・終了結果を検証する。
4プロセスすべて成功時に `MOCK_LAUNCHER_OK` を表示する。
手動操作用の3ウィンドウも実アセットで起動し、それぞれのオンラインメニューへの到達を確認した。
