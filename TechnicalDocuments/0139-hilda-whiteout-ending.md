# ヒルダ撃破のホワイトアウトとエンディング

2026-10-11。原作のストーリーではボスのヒルダを倒すと、勝利ポーズに進まずホワイトアウトし、
ロード画面を挟まずエンディングデモが始まる（ユーザー確認）。本作は通常どおり勝利ポーズ→ロード絵→デモだった。

## 原作データの仕組み

ストーリー表の最終戦エントリは時間0・ステージ「ラスト」以外は通常戦と同じで、専用のフラグはない。分岐はスクリプトにある。

1. ヒルダの「開始時」#21 がシステム変数130を1100にする（本作は `startRound` で相手のキャラ番号として同値を設定）。
2. システム #55「勝ちマークＯＮ」:
   - ブロック1: V140（ストーリーの難易度 1000/2000/3000）が995未満なら通常アニメへ。
   - ブロック2: マーク自身のx座標が244（1P側2つ目＝試合を決めたマーク）ならブロック40へ。
   - ブロック40で130に+1、約150フレーム後のブロック64で-1。
3. ヒルダの「負け」#23 は開始直後（0・2・約21フレーム目）と「死」#29 で `V130 = 1101` を調べ、成立すると #23 ブロック57へ。
   画面揺れ・音の後、深さ127のオブジェクト #302 を生成する。#302 は画像643を加算合成し、色を足し続けて最後は (32,32,32)＝真っ白で保持する。
   ラウンド終了 #14（深さ125）の暗転より手前なので、そのまま白い画面で試合が終わる。

## 原作で分岐が成立する時機（推定）

- 勝ちマークは「KO」の文字の登場アニメーションの終わりに点灯する（ユーザー確認。勝利ポーズ開始ではない）。
  #26 KO の表示時間は100フレームで、文字の登場・保持が約115フレーム、その後約12フレームで透明化して退場する。表示時間切れ＝登場の終わり頃。
- ユーザー確認: ゆいの風神Aでとどめを刺すと、風神Aの最終ポーズのままホワイトアウトしてエンディングへ。
  #23 ブロック57冒頭の `PS 0, 255`（相手を255フレーム停止）で説明できる。
- ヒルダの確認は #23 の0〜21フレーム、#29 の0〜58フレームのみで、KOから約100フレーム後のマークには通常間に合わない。
  原作は体力0で負け技を保留遷移にする（0105、0x40E823）ため、空中のやられ動作が終わって #23 を始める頃にマークが点灯し、重なると考えられる。
- 本作は0105の方針で体力0の瞬間に #23 を始めるので重ならず、分岐しなかった。

## 変更

- `src/round.lh`: 勝利数とマークの加算を、KOの表示時間切れ時点へ移動（勝者の技の終了は待たない。勝利ポーズの開始は従来どおり技の終了待ち）。
  `awarded` で1ラウンド1回。KO待ち上限時も未加算なら加算。
- `lossWithMark`: 試合を決めるマークの点灯と同時に、敗者の #23 を始め直す。ヒルダ自身の #23 がマークの130=1101を見てブロック57へ分岐する。
  ブロック番号は持たず、分岐はデータに任せる。ユーザー指定により `main.lh` がストーリーのヒルダ戦だけ有効にする。
  保留遷移そのもの（全キャラのKO動作に影響）は再現しない。
- ストーリー: ヒルダに勝って試合が終わったら、次のロード中はロード絵（0031の追加演出）ではなく白一色を表示し、黒からのフェードも省く。
  デモ開始で解除。原作は同期読み込みのため、ホワイトアウトからそのままデモに入る。

## エンディングデモ間のロード（2026-10-12）

撃破後のストーリー表は エンディング１ → エンディング0（はるかは エンディング２ → エンディング0）。
演出がつながっているのに、間にロード絵が出ていた（ユーザー指摘）。原作は同期読み込みなので画面は止まるだけ。

- `State.ending`: ヒルダ撃破で立てる。以後、デモの次がデモなら、終わったデモを破棄せず表示し続ける（最終フレームで停止）。
- 次のデモの読み込み完了時（`completeLoad`）に、保持していたデモの arena を pop してから新しい arena を attach する。
  ロード画面の最短表示（0.3秒）は、保持中は待たない。
- デモ名では判定しない。ヒルダ撃破後のデモ→デモがすべて対象。
- `tests/ending-chain.lh`（`tools/test-async.ps1 -Test ending-chain`）: 実データでエンディング１→エンディング0を流し、
  2本目のロード中は前のデモが保持され、開始時に arena が `system / select / story / story-event` へ戻ることを確認。
  `story-continue`・`story-navigation`・`story-memory-return`・`hilda-whiteout`・`victory-preload` PASS。
- テスト用に `vp.main.story()`（実行中のストーリー状態）を公開。
