# VS のリプレイ記録と再生

2026-10-15。ロールバック型ネットコードの前段として、入力だけで試合を再現するリプレイを作った（ユーザー指定）。
VS MODE の試合を自動で記録し、WATCH REPLAY（[0154](0154-replay-list.md)）の一覧から再生する。

## ファイル

- セーブディレクトリの `replays/<1P>vs<2P>-<YYYYMMDD-HHMMSS>.replay`（`src/replay.lh`）。キャラ名は `assets/characters/` のフォルダ名（ゆい など）。
  同名があれば `-2`, `-3` … を付ける
- **日時は UTC**。L^ にも LÖVE にも暦の時刻を得る API が無い（`love.timer` は単調時計、std に time が無い）。
  `replays/.now` を書いてその更新時刻（`getInfo().modtime`、Unix 時刻）を読み、暦日に変換している。
  タイムゾーンは得られない
- 中身は `std.binary` で詰める（固定長の形式のみなので、ヘッダ1つ＋フレームを並べる）
  - ヘッダ: magic（"VPRP"）、version（1）、乱数シード、1P/2P のキャラ（`vp.select.CHARACTERS` の番号）・カラー（選択画面で選んだ値。2P の同キャラ時の色ずらしは再生時に再計算）・サポート（システム変数 142/143）、
    ステージ番号、ラウンド秒数、勝ち抜け数、フレーム数、結果（勝利数・最終体力。再生の一致確認用）
  - フレーム（1P/2P 各11ビット、計3バイト）: 方向（上1・下2・左4・右8。テンキー番号でなくビットなのは、左右同時押しを前方・ガード（後方）が別々に読むため）、ボタン（A=1 … F=32、F も含む）、CPU フラグ
- 100 フレーム/秒 × 3 バイト。60 秒ラウンド3本でも 60KB 程度

## 記録

- VS（練習・ストーリー以外）の試合開始（`startBattle`）から試合終了（`toSelect`）まで、毎 tick の両者の入力を記録し、終了時に保存。
  試合前の待ち（入力が効かない tick）も含めて全 tick を記録する
- 入力はキー・パッドの状態から作った「記録用の値」を、記録・再生とも同じ経路で `control` に渡す（記録時と再生時で解釈が分かれない）

## 決定性

入力だけで再現するために以下を揃えた。

- **シミュレーション専用の乱数**（`src/rng.lh`）: スクリプトの `Rnd`（`fighter.chance`）、CPU の思考、画面揺れのモード4 はこちらを使う。
  以前はすべて `love.math.random` を共有していて、描画時に呼ばれる残像のちらつき（`afterimage.weight`）が fps に応じて乱数を消費していた。
  残像は見た目だけなのでグローバルのまま。メニュー側（ステージ抽選など）もグローバルのまま
- **シード**: 試合ごとに新しいシードを作り（`loadMatch`）、VS 演出の開始（`beginPresentation`、ステージのスクリプトのため）と試合開始（`startBattle`）でシードし直す。シードはヘッダに保存
- **試合開始のフレームを固定**: 以前は読み込みが終わった時点で `startBattle` し、演出の経過フレーム（`presentationFrames`）だけキャラを裏で進めて追いつかせていた。
  経過フレームが読み込み時間で変わるので、演出の残りのフレーム数（＝試合開始までの tick 数）も変わっていた。
  VS では演出がアセット待ちで止まる地点（`flow.waitingForAssets()`、#111 の image 207 の保持が終わったところ）まで `startBattle` を待つ。
  キャラはこの地点より前は表示されない（背景のみ、`battleRevealed` 前）ので見た目は変わらない。待つのは早く読み終わった場合だけで、遅い場合は従来どおりそこで止まっている
- **CPU**: CPU は1フレームの入力でなく、コマンド全体を入力履歴に書き込む（`recordCPU`）。方向・ボタンでは表せないので、CPU が操作したフレームは CPU フラグだけを記録し、
  再生時は同じフレームで同じ CPU（レベル100）を作って動かす。同じシードの乱数から引くので同じ判断になる

### 再現しないもの（開発用キー）

G（ダミーのガード）、F2（相手の体力を1に）、1〜8（パレット。見た目のみ）は記録しない。記録中に使うと再生がずれる。

## 再生

- WATCH REPLAY の一覧で選ぶ（`startReplay`）。ヘッダから VS と同じ手順で読み込み（ステージ → 演出開始 → キャラ）、演出が始まるまでモードメニューを表示したまま
- 毎 tick、記録の入力を流す。キー・パッドの入力は無視。記録が尽きたらニュートラル
- 試合終了で、フレーム数・勝利数・最終体力を記録と比べてログに出し（`Replay ended as recorded` / `NOT as recorded`）、モードメニューへ戻る
- 再生中 ESC で中断してモードメニューへ。Start（Enter）は一時停止

## F3 / F4（開発用）

VS で F3 が 1P、F4 が 2P を CPU（レベル100）にする／戻す。選択画面でも試合中でも切り替えられ、次のフレームから効く。セッション中は保持。
試合中の切り替えも記録される。音声ログは F3 から F5 へ移した。

## 検証

- `tests/replay-roundtrip.lh`（`-Test replay-roundtrip`）: 5秒ラウンドの VS を F3/F4 で CPU 同士にして記録 → WATCH REPLAY で再生し、
  フレーム数・勝利数・最終体力が一致することを確認（3610 フレーム、2-1、体力 940/899 で一致）。テスト用のリプレイは消す
- `tests/replay-format.lh`（`-Test replay-format`）: ヘッダ全項目と、方向・ボタン・CPU フラグが様々な 1000 フレームが、保存・読み直しで変わらないこと
- `tests/gauge-random.lh`（`-Test gauge-random`、test-async に登録）: `Rnd` の期待値をシミュレーション用乱数で計算するよう変更
- VS を最後まで遊ぶ既存テスト（`vs-memory-return`）は、保存されたリプレイ（`status().lastReplay`）を消す。テストが本物のリプレイを残すと `replay-list` の一覧の位置がずれるため
