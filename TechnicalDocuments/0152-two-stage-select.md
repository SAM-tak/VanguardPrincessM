# キャラ・パレット決定後にサポートを選ぶ

ユーザー指定の変更。キャラセレをmain → support → readyの2段階確認にする。STORYは1Pのみ、VSは各プレイヤー独立、PRACTICEは1Pの両段階が済んでから相手側の両段階へ入力を引き渡す。

## 入力

- main: 上下で10キャラ、左右で6パレット（0〜5）を選ぶ。攻撃ボタンの種類によるパレット決定は廃止し、A/C/E/Fでメインを確定する。B/Dでは決定しない。
- support: メインのキャラ・色は固定。左右で「かなえ・シエラ・えこ・ジュリエット」の並びを選び、欄外ではヒルダを含むルーレットに入る（詳細は0153）。A/C/E/Fで確定する。B/Dでメイン決定前へ戻る（キャラ・色・現在のサポートを保持）。サポートの色番号はメインと同じ（ユーザー確認済み）。
- ready: 両方決定。従来の待ち時間を経て次の場面へ。サポート決定後はB/D・ESCで取り消せない。ESCもsupportからmainに戻る操作だけに限定し、決定済みの側があるときはキャラセレ全体を終了して決定を破棄しない。VSの試合後にキャラセレへ戻るときはキャラ・色・サポートを復元する。

Select.Sideがphase・colour・supportを保持する。横入力の方向変化を1回の操作として扱う。メイン決定の入力を同じフレームでサポート決定や次のプレイヤーへ流さない。

キャラのportraitスクリプトへの方向入力はneutralにし、元のCOMがサポート選択を勝手に変えないようにする。サポート変更はrestoreSupportで元の対応するV命令の位置から再開し、描画資源とサポート表示は原作のものを使う。確認フラグは最終決定後だけ立てる。

## 表示

mainではメインの顔が明るく、サポートの顔・アイコン・名前が暗い。supportではメインの顔が暗く、サポートが明るい。readyでは両方明るい。sprite shaderのbrightnessでRGBを乗算する（暗いものは0.35）。スクリプトのCOLORやalphaは変えず、各描画の後でbrightness=1へ戻す。

旧操作説明のキャラセレ画像4・5は両ロケールで描画しない。背景なしの6色の四角形をサポートアイコンの上に重ねる（1Pの左端x=80、2Pはx=430、y=363、16px角、間隔21px）。選択中の枠を白くする。パレット列はmain中だけ表示し、support・readyでは非表示。B/Dでmainへ戻ると同じパレットが選択された状態で再表示。下端に段階名と操作説明を白文字・黒縁で描く。日英ともdata/locale/<lang>/images.ltonの既存形式を使い、ロケール生成器の機能は追加していない。

代表色はdata/select-palettes.lton。tools/locale/select_palette_colours.pyで原作のパレットを参照し、各キャラの大きなindexedポートレートに含まれる色から、6行で区別できる色を優先し、使用頻度と変化量で代表インデックスを選ぶ。元画像は変更しない。

## 検証

- select-stages: 全10キャラの6パレットの循環・同キャラ同色の補正、4サポート、長押しで二重移動しないこと、ボタン別に色が変わらないこと、B/Dによるメイン選択取り消し、B/Dで決定しないこと、確定済みのサポートがB/D/ESCで取り消されないこと、パレット列の表示条件、確認待ち中のサポート/色維持、VS独立、練習モードの引き渡し（PASS）。
- async-flow / practice-mode / story-flow / story-navigation / vs-memory-return / f8-main-reload（PASS）。VSからselect/menu/titleへの3往復でも資源解放と同期読み込みゼロを確認。
- 既存進行テストのpressヘルパーはtests/select-input.lh経由で、必要なときだけメイン・サポートを2回の入力で確認する。個々の入力の意味は専用select-stagesで直接検証する。
- 実エンジンのdrawをCanvasへ描画してreadbackし、日英のmain/support/readyと、片側がsupport・もう片側がmainのVSを目視確認。プレビューはbuild/select-preview/（Git対象外）。設定ファイルは退避・復元。

変更した既存進行テスト10本も、runnerと同じゲームルートの入口にしてコンパイル成功。

メイン決定時にも原作のシステム音声7番を再生する。左右の欄外ルーレット・ヒルダ・表示同期の詳細は[0153](0153-support-roulette.md)。

## パレット数と同色補正（2026-10-15更新）

選択肢は6色（0〜5）。PALETTE_COUNTで左右の循環・表示数・同キャラ同色時の2P補正を共通化する。補正はopponentColourで行い、6番目同士なら2Pを1番目にする。対戦前ポートレート・VS/PRACTICE本体・STORYの同キャラ相手に適用。元データの256×8テクスチャとデバッグ用1〜8キーは保持する。8行目は多くのキャラで1行目と同一だが、あやね・サキ・ナタリアでは異なるため、内部データが6色だけというわけではない。

メイン決定（support移行）で同キャラのその色を占有する。後から選ぶ側は左右移動で占有色を飛ばし、キャラ変更時や先行側の決定時に重なっていれば次の色へ移す。占有色の四角形は暗くする。B/D/ESCでmainへ戻ると占有解除。readyでは維持する。同一フレームの同色決定は処理順の1Pを先とする。対戦開始時のopponentColourはフォールバックとして残す。select-stagesで両方の決定順・全6色・左右スキップ・キャンセルによる解放を検証する。

2026-10-15のユーザー訂正により、選択肢は6色へ戻した。色の占有・スキップとフォールバックは6色の範囲で循環する。7行目以降は選択肢には加えず、元データとして保持する。
