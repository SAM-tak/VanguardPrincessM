# LAN VS MODE（遅延方式）

2026-10-15。LAN VS MODE で実際に通信対戦できるようにした（ユーザー指定）。まずは**遅延方式**（入力を数フレーム先送りし、
相手の入力が届くまでフレームを止める）で、探索・接続・選択画面・試合・切断を一通り動かす。ロールバックは
スナップショットを軽くしてから（[0156](0156-snapshot-rewind.md) で取得 7ms、1フレームは 10ms）。LAN なら往復 1ms 未満なので
遅延方式でも遊べる。

## 画面の流れ（`src/lanmenu.lh`）

- モードメニューの LAN VS MODE（6番目）で、WATCH REPLAY と同じ形の小窓を開く: 「ホストする／LAN 内を探す／戻る」
- **ホスト**: 「対戦相手を待っています…」と自分の IP:ポートを表示。相手が来たら自動で受け入れる
- **探す**: 答えたホストの一覧（IP。対戦中のものは「対戦中」で選べない）。A で接続、3 秒答えが無ければ失敗の表示
- B / D・ESC で一段戻る（接続をやめる）。名前の入力は無い（IP を出す。ユーザー指定）。IP の直接入力は後回し
- 接続したら両者とも VS の選択画面へ。ホストが 1P、ゲストが 2P。どちらも自分の機械の 1P キー（とパッド）で自分の側を操作する
- 相手の側は**確定した選択だけ**が届き（`Select.applyChoice`）、それまで「選択中…」を出す（ユーザー指定。カーソルの動きは送らない）
- 試合後は選択画面に戻って次の試合。ESC で抜ける（試合中は一時停止しない。Start も効かない）。
  相手が抜ける（BYE）か 3 秒何も届かなければ、モードメニューに戻って理由を表示
- 両者とも試合をリプレイに記録する（[0155](0155-replay.md)）

## 通信（`src/net.lh`）

std.net の UDP（受信は待たない。毎フレーム空になるまで読む）。メッセージは std.binary の形式で、
先頭に magic（16 ビット）と種類（8 ビット）。

- **探索**: ホストは固定ポート 7650 に bind。ゲストは任意のポートからブロードキャスト（255.255.255.255）と 127.0.0.1 に QUERY を
  0.5 秒ごとに送り、ホストが BEACON（版・対戦中か）を返す。ゲスト側が問い合わせる向きなので、同じ機械の別プロセス同士でも試せる
- **接続**: ゲストが JOIN（版）を 0.2 秒ごとに送り、ホストが ACCEPT（版が違えば REFUSE）。ACCEPT が失われたら次の JOIN にもう一度返す
- **選択**: 各側が自分の選択（選択の回・確定したか・キャラ・カラー・サポート）を 0.1 秒ごとに送る。相手のものは回が今の回で確定済みなら反映する
- **試合の設定**: ホストが試合の読み込みを始めるとき、回・乱数シード・ステージ・ラウンド秒数・勝ち抜け数を決めて送り続ける。
  ゲストはこれが届くまで読み込みを始めない
- **入力**: フレーム f の入力をフレーム f−3 で取り（`INPUT_DELAY = 3`）、毎フレーム直近 8 フレーム分をまとめて送る
  （1つ落ちても次で埋まる）。1 側 11 ビット（方向4・ボタン6・CPU フラグ。リプレイと同じ詰め方）。最初の 3 フレームは両者ニュートラル。
  フレームは両者の入力がそろうまで進めない（相手の入力が 0.3 秒以上来なければ「相手を待っています…」）
- **ずれの検出**: 100 フレームごとに、シミュレーション乱数の状態・両者の体力・x 座標を交換して比べ、違えば `DESYNC` をログに出す
- **切断**: BYE、または 3 秒無受信

試合の開始フレームは VS と同じくアセット待ちの地点に固定してある（[0155](0155-replay.md)）ので、読み込み時間が違っても両者のフレームは一致する。

### CPU（F3）

LAN VS でも F3 で自分の側を CPU にできる（F4 は無効）。CPU フラグは入力と一緒に送られ、相手側でも同じフレームから
同じ CPU を同じ乱数で動かす。テストはこれで CPU 同士の通信対戦を走らせる。

### 自分のアドレス

std.net には自分のアドレスを聞く口が無いので、別のソケットを外向きのアドレス（192.0.2.1、文書用の予約アドレス。送信はしない）に
`setPeer` して `getLocal` で得る。複数の NIC がある機械では、表示されるアドレスと探索側に見えるアドレス（応答の送り元）が
違うことがある（この機械では WSL / Hyper-V の仮想アダプタ 172.28.224.1 が見えた）。

## 検証

- `tools/test-lan.ps1`: `tests/lan-vs.lh` をホストとゲストの 2 プロセスで同時に動かす。ホストが待ち受け、ゲストが探して接続し、
  両者 F3 で CPU にして 5 秒ラウンドの試合を通信で行う。両者が記録したリプレイのフレーム数・勝敗・最終体力・シードが一致し、
  ずれの検出（24 回）がすべて一致することを確認（2423 フレーム、0-2）
- 途中で見つかった不具合: 試合後に選択画面の行を `characterCode / 100 - 1` で戻していて実数になり、std.binary の整数検査で止まった（`floor()` で修正）
