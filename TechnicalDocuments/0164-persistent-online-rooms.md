# 名前付きオンラインルームと対戦台

2026-10-15。Online VSの単発接続を、試合後も残る複数人ルームに変更した。
参考はユーザー指定の [SF6カスタムルームの画面](https://game.watch.impress.co.jp/img/gmw/docs/1495/312/html/5.jpg.html)。

## 画面と操作

- 認証方法を選択後、「ルームを作成」「ルームを探す」を表示する。
- 作成時にルーム名、任意の暗証番号、プレイヤー名を入力する。参加時は暗証番号とプレイヤー名を入力する。暗証番号なしの部屋は空欄で参加できる。
- `love.keyboard.setTextInput` と `textinput` コールバックでUTF-8入力を受け取る。入力中は通常のゲーム用キー割り当てを止め、Z/X/Aなども文字として扱う。Tab／上下で項目移動、Enterで確定、ESCで戻る。BackspaceはUnicodeの文字単位で削除する。Ctrl/Cmd+Vで貼り付け可能。日本語IMEの実キーボード操作は別途確認が必要。
- ルーム名は24文字、プレイヤー名は16文字。暗証番号は空欄または4〜8桁の数字で、入力欄では伏せ字にする。プレイヤー名は既存の `settings.json` に保存する。
- 検索結果には実際のルーム名、鍵の有無、人数を表示する。自動の「Lobby 1」などは使わない。
- ルームは最大16人・対戦台4台。1280×960の画面上に1180×820の大きなパネルを重ね、左に対戦台、右に参加者一覧を表示する。ホストに星印、自分の名前に色を付け、席番号も表示する。
- 上下で対戦台、左右で1P／2Pを選び、決定で着席。同じ席でもう一度決定するとREADYを切り替える。両側がREADYになると、その2人だけがキャラ選択と試合へ進む。
- ロビー内の離席・退出はEsc／ゲームパッドのBackのみ。B/Dは誤退出防止のため無効。待機状態からEsc／Backを押すとルームを退出してHost／Search選択へ戻る。試合終了待ちでも離席できる。試合途中のESCは対戦を中断してルームへ戻る。
- 試合後は同じルーム・同じ席へ戻り、READYを解除する。再度双方READYにすれば次の試合を始められる。ほかの対戦台の試合は継続する。

## 構成

`src/lobby.lh` が所有者側のルーム状態を管理し、二重着席、1人の複数席占有、対戦中の席移動を防ぐ。対戦開始ごとに単調増加する番号を発行し、参加者とREADY状態を確定する。部屋主自身が対戦していない台でも開始できる。1P／2Pは部屋主かどうかではなく着席側で決まる。

`src/online.lh` はEOSの参加者IDを用いて入室を受け付け、所有者が承認した参加者だけを名簿に載せる。EOS P2Pのchannel 1で所有者が名簿と対戦状態を配信し、各参加者が自分の席・READY・終了を要求する。名簿は開始／参加者ごと／終了に分けてEOSの1170バイト制限内で送る。受信側は同じ版の配信が揃ってから適用する。

既存の対戦データはchannel 0で対戦相手へ直接送る。ロビーIDと対戦番号を付け、前の試合や別の台の入力を受け付けない。試合終了時は相手が最終入力まで受信したことも確認してから戻る。部屋自体のEOSセッションは退出しない。

`main.lh` は試合終了時にリプレイを保存してキャラクター資源を解放し、モード選択画面とルームパネルへ戻る。LAN対戦の終了後の挙動は維持する。`src/roommenu.lh` がオンライン画面を担当し、`src/lanmenu.lh` はLAN画面とオンライン画面の振り分けを行う。

新しいbucketは `vanguard-m-0164-room-v1`、socketは `vanguard-room-v1`。初期の2人用オンライン版とはルームを分ける。

## EOS拡張

`C:/Users/Owner/source/repos/eos-lhat` に以下を追加し、DLLと模擬DLLを再ビルドした。

- `setRoom(name, locked)`：所有者がルーム名と鍵の有無を公開属性 `vp_name` / `vp_locked` として設定する。
- ロビー情報に `name` / `locked` を追加する。検索結果からも読める。
- `kick(peerId)`：所有者が入室を拒否したユーザーをEOSロビーから退出させる。
- 完了イベント `roomUpdated` / `kicked`。既存イベントの番号は維持する。

暗証番号そのものは公開属性・検索結果・名簿へ載せない。参加者から所有者へのP2Pメッセージで照合し、不一致なら参加を拒否して退出させる。この暗証番号はゲーム内の入室制御であり、EOSがサーバー側で検証するパスワード機能ではない。

部屋主の退出ではルームを終了する。所有者の交代によるルーム継続、観戦映像、チャットは今回の対象外。待機中の参加者はほかの対戦台の進行状況を名簿で確認できる。

## 検証

- `tools/test-online.ps1`：5つの独立したリンクを模擬EOSで動かし、UTF-8フォーム、名前・人数・鍵付き検索、暗証番号不一致の拒否、名簿同期、同時着席、双方READY、部屋主を含まない対戦、2台同時対戦と入力分離、試合後の席保持・再READY・新しい対戦番号、参加者と部屋主の退出を確認。ソースと配布用VMで成功した。
- `tools/test-online-game.ps1`：実際のゲーム本体と入力送信だけの模擬対戦相手で試合を進め、リプレイ保存、ルーム維持、ロビーパネルへの復帰、再READYから次のキャラ選択へ進むことを確認した。元データは `data/` / `assets/` への生成先内のジャンクションで参照し、本物のEOS設定は使わない。
- LAN障害試験：3690フレームを完走し、両者の36回の状態要約・入力・終了結果・巻き戻しなしのリプレイが一致した。

- 実EOS：検証専用bucketで日本語名・鍵あり・定員16人の公開ロビーを作成し、その名前と鍵の有無が検索結果へ反映されることを確認して退出した。暗証番号の参加者照合と複数PCでの同時対戦は模擬EOSの検証のみ。
