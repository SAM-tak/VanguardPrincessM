# リプレイのラウンド別記録

`src/replay.lh` の新規保存をversion 2に変更。試合は従来どおり1ファイルとし、入力をラウンド別のブロックに分ける。観戦で現在のラウンドを渡すための前段階。

## 形式

従来と同じ36バイトの試合ヘッダ（versionのみ2）、uint32のラウンド数、その数だけラウンドブロックを並べる。

各ブロックは24バイトのヘッダと入力列:

| 項目 | 型 | 意味 |
| --- | --- | --- |
| first | uint32 | 試合全体での先頭フレーム（0起点） |
| number | uint16 | ラウンド番号（1起点、引き分けでも進む） |
| wins1 / wins2 | uint8 × 2 | 開始時点の取得ラウンド数 |
| random | uint32 | 開始フレームのシミュレーション用乱数状態 |
| frames | uint32 | このブロックの入力フレーム数 |
| special1 / special2 | int32 × 2 | 開始時点の両者のスペシャルゲージ（ストック数ではなくポイント） |

入力は従来と同じ1フレーム3バイト、両者の方向・A〜F・CPUフラグ。ラウンド開始演出・戦闘・終了演出を含む。ラウンド遷移を行うtickは直前ブロックに含み、次のtickを新ラウンドの先頭とする。

`Tape.rounds` は境界情報、`roundFrames(index)` はラウンドの長さ、`encodeRound(index)` は指定ブロックの符号化。実行中の `side1/side2` は既存の再生・巻き戻し・ロールバックとの互換性のため試合全体の配列として保持する。ファイル内では入力を重複保存しない。

## 記録と互換性

`battleStep` の入力記録前に `markRound` を呼び、番号が変わった最初のフレームだけ境界を追加。ネット対戦の再シミュレーションでは、そのフレーム以降の予測による境界を除去して記録し直す。最終入力の切り詰めも `Tape.truncate` で入力・境界の両方に適用する。

version 1は従来どおり再生可能。元データに境界がないため `legacy = true` とし、ラウンド不明の入力列を1ブロックとして読み込む（開始情報は補完できない）。新形式ではブロックの欠落、余剰データ、先頭フレームの不連続、不正なラウンド番号・フレーム数を拒否する。

## 次の段階

この段階の対象は記録形式と既存の通し再生の維持。再生中のラウンド移動と直接再生は[0170](0170-replay-round-start.md)で追加した。途中参加・観戦配信はまだ追加していない。

ラウンド開始時に `startRound` が立ち状態へ戻し、技・オブジェクト・キャラ変数を初期化するため、戦闘中の技コルーチン保存は不要。途中ラウンドからの再生は、ゲージ・勝利数・乱数状態などを設定して通常の開始処理に入る形を基本とする。ただしステージのスクリプトはラウンドをまたいで進行しているので、その再現方法は別途必要。今回の境界ヘッダを完全な復元用スナップショットとは扱わない。

## 検証

- `replay-format`: 3ラウンド・1000フレームの全項目往復、旧version 1入力の読込、ロールバック時の境界差し替え、入力切り詰め。
- `replay-roundtrip`: 実際のCPU対戦が複数ラウンドに分割され、全フレームを過不足なく格納し、通し再生のフレーム数・取得ラウンド数・最終体力が一致すること。
- `replay-controls`: 早送り・巻き戻し後も試合結果が一致すること。
- `tools/test-online-game.ps1`: 模擬EOSで実ゲームの試合終了・リプレイ保存・同じルームへの復帰・再対戦を確認。
